## 欢迎使用 Tyndall

Tyndall 是一个现代化、注重细节与视觉体验的 Astro 个人博客主题。

### 主要特性

- 🎨 **精美设计** - 细腻的视觉效果和流畅的动画
- 🌓 **深色模式** - 支持亮色/暗色主题切换
- 🌍 **国际化** - 内置中英文双语支持
- 📱 **响应式** - 完美适配各种设备
- ⚡ **高性能** - 基于 Astro 构建，速度超快
- 🎵 **文章里的音乐** - 用一行指令插入 Apple Music 歌曲、专辑或歌单
- 🗺️ **旅行地图** - 在游记中标记地点、按天切换行程
- 📝 **随手记录** - 给 Telegram Bot 发消息，就能发布碎碎念
- 🟢 **实时状态** - 配合 Nowcast 分享正在做的事和播放中的音乐

### 开始使用

1. 克隆项目
2. 安装依赖：`pnpm install`
3. 启动开发服务器：`pnpm dev`
4. 开始创作你的内容！

站点信息、部署和服务接入可以接着看[配置指南](/blog/config)。下面先试试几种 Tyndall 自己的写法。

## 🎵 把音乐放进文字里

写到一张喜欢的专辑时，不必只留一个跳转链接。在 Apple Music 中选择「分享 → 拷贝链接」，把它放进正文里的一行指令：

```markdown
散步的时候，想给这篇文章配一点音乐。

::apple-music{url="https://music.apple.com/us/album/how-to-be-a-human-being/1440840097"}

音乐之后，接着写今天的故事。
```

实际效果如下：

::apple-music{url="https://music.apple.com/us/album/how-to-be-a-human-being/1440840097"}

歌曲、专辑和公开歌单都可以使用分享链接。单曲链接中的 `?i=歌曲ID` 要保留，否则可能变成整张专辑。单曲默认高度为 175px，专辑和歌单为 450px，也可以用 `height="300"` 自己调整。

这是一条**独占一行的块级指令**，前后留空行即可，不需要自己写 iframe 或配置 Apple API key。播放体验由 Apple 的播放器提供，可能受地区、登录状态和内容可用性影响；主题不会把音频下载到你的站点。

## 🗺️ 给游记加一张地图

把地点写进文章开头的 frontmatter，再在正文中放上地图指令。比如这段虚构的巴黎散步路线：

```yaml
map:
  days:
    - day: 1
      color: '#a259ec'
      stops:
        - name: 埃菲尔铁塔
          coords: [2.2945, 48.8584]
          note: 从这里开始今天的散步
        - name: 卢浮宫
          coords: [2.3376, 48.8606]
```

将上面的 `map:` 合并到文章已有的 `---` 区域内，与 `title`、`pubDate` 同级。正文中另起一行：

```markdown
::travel-map{height="480"}
```

这篇文章的地图就是这样生成的，可以拖动、缩放并点击地点：

::travel-map{height="480"}

`coords` 的顺序是 **[经度, 纬度]**。`stops` 按游览顺序排列，默认用直线连接，只表示行程顺序，不是步行导航；多日行程继续添加 `day: 2`、`day: 3` 即可，每天可以使用不同颜色。

地图直接使用文章的数据，不依赖照片 EXIF，也不需要先创建 `/travel` 相册。底图需要联网加载；自驾贴路路线、自定义底图等设置见[配置指南](/blog/config)。发布前记得检查地点是否适合公开。

## 📝 不用打开编辑器的碎碎念

配置好 Telegram Bot 后，发一句「今天读完了一本书 #阅读」，或者发一组带说明的照片，就能出现在 Memos 页面。博客从 Supabase 读取新内容，不用为每条碎碎念重新部署。

Telegram 的部署方法、命令和图片存储都写在[配置指南](/blog/config)里。飞书、Discord 可以扩展相同的发布流程，但目前还没有随主题提供对应接收端。

## 🟢 让博客知道你现在在做什么

Nowcast 可以把当前活动和后台 Apple Music 信息送到博客的“现在在做”卡片，例如「正在用 Obsidian 写文章」。这是会过期的实时状态，不会自动生成一篇文章或一条 Memo，也不会改动音乐专辑墙。

安装客户端后还需要配置接收接口和写入密钥，步骤见[配置指南](/blog/config)。先选好愿意公开的活动文案，再开始共享。

## 🔧 把日常工具放进实验室

实验室可以展示写作节奏、最近收藏、服务器指标和自建服务。它们不是访客打开页面时实时查询的：写作节奏来自 Git 历史，收藏和服务器指标通过 Karakeep、Beszel 的 API 获取，再由 GitHub Actions 保存快照、触发博客重建。

公开版先放了示例数据，你可以只接入自己需要的部分，也可以手动维护。所需变量、工作流和数据公开范围见[配置指南](/blog/config)。
